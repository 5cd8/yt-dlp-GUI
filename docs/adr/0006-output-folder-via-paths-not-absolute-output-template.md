# 動画取得の出力先は、一時フォルダを使うときだけ `-P home:` で渡し、`-o` はファイル名だけにする

長時間の動画では、動画取得の後のyt-dlpの後処理（FixupM3u8・Metadata・EmbedThumbnail）が、出力先の外付けHDD上で巨大なファイルを何度も読み書きし直すために遅い。そこで、中間ファイルを高速なドライブに置けるよう、設定に「一時フォルダ」を足し、yt-dlpの `-P temp:` で渡す。ところが、`-o` に絶対パスを渡していると、yt-dlpは `WARNING: --paths is ignored since an absolute path is given in output template` を出して `-P` を無視し、中間ファイルはすべて出力先に作られる（yt-dlp 2026.08.19で確認）。そこで、一時フォルダを設定したとき（ライブ録画を除く）は、出力先を `-P home:<出力先のフォルダ>` で渡し、`-o` はファイル名だけにする。この形では、取得・結合・メタデータ・サムネイルの埋め込みがすべて一時フォルダで行われ、最後に `[MoveFiles]` で完成物だけが出力先へ移され、成功後に一時フォルダは空になる。一時フォルダが空欄のときは、引数を今までと同じにする。

## Considered Options

- `-o` を絶対パスのまま、中間ファイルを自前で移す: yt-dlpの後処理が出力先で行われるので、速くならないため却下。
- 常に `-P home:` の形へ組み直す: 一時フォルダが空欄のときの引数が変わり、「空欄なら今まで通り」を保証しにくくなるため却下。

## Consequences

- 一時フォルダは完全な絶対パス（ドライブ付き、または `\\サーバー\共有`）で渡す。ルート相対（`\work\tmp`）・ドライブ相対（`C:tmp`）・相対パスだと `home:`（出力先）からの相対になり、中間ファイルが出力先の中に作られてしまうので、設定画面が保存時に拒む。
- ライブ録画には一時フォルダを渡さない。ライブ録画の仕上げ（`FinalizeLiveOutputFileAsync`・`LivePartMerger`）が、出力先にある途中ファイルを探すため。
- 失敗・中止で一時フォルダに残った途中のファイルは消さない。同じURLの再実行とアプリのリトライが、続きからの再開に使う。
- `[MoveFiles]` は、別ドライブへはコピーしてから元を消す。この最中に中止・失敗すると、出力先に途中までのファイルが完成名で残り、再実行で yt-dlp が「取得済み」と扱うことがある。空き容量を事前に確かめないことと、掃除しないことの帰結で、既知の制約として受け入れる。
