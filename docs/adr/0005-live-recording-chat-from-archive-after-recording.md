# ライブ録画のチャットは、録画と同じyt-dlpで取らず、録画の後にアーカイブから別のyt-dlpで取る

YouTubeのライブ録画で、動画取得と同じyt-dlpに`--write-subs --sub-langs live_chat`を付けると、yt-dlpは動画より先に配信中のチャット（`youtube_live_chat`）を取り始め、配信が終わるまで動画の録画に進まない（2026-10-03に実機で確認。yt-dlp自身も「動画を同時に取るなら別のyt-dlpを起動せよ」と警告する）。しかも配信中に取れるチャットには`timestampText`が無く、vlc-chatは全件を読み飛ばすので、同期再生に使えない。そこで、ライブ録画では録画中にチャットを取らず、配信の終了で録画が終わった後に、別のyt-dlp（`--skip-download`）でアーカイブのチャットリプレイを取る（ADR 0002と同じ逐次実行）。長い配信ではチャットリプレイがすぐには用意されないため、取れなかった項目には「チャット未取得」の印を付け、後から右クリックで取り直せるようにする。ライブ以外の動画は、ADR 0003のとおり動画取得と同じyt-dlpで取る。

## Considered Options

- 配信中のチャットを、別のyt-dlpで録画と並行して取る: yt-dlpの警告が勧める方法だが、取れるチャットはvlc-chatが使えない形式で、しかも1キュー項目に2つのプロセスを持つことになり、ADR 0002の前提（進捗表示・完了判定・中止処理）を作り直す必要があるため却下。
- ライブの項目ではチャットリプレイ取得を選べなくする: 一番多い使い方（配信を最後まで録画する）で、追加の操作なしにチャットが手に入らなくなるため却下。

## Consequences

- 停止・項目の中止で録画を途中で終えた項目は、配信がまだ続いていてチャットリプレイが無いので、最初から「チャット未取得」になる。
- キュー項目は保存されないので、アプリを閉じると「チャット未取得」の印も消える。
